# 社内向け詳細版：遺言・遺産整理BPO支援システム 開進捗報告

---

## 1. 全体導線（Home/サイドバーのメニュー構成）
- Home（エントランス）とサイドバーによる業務メニュー遷移
- 各機能ページは `src/legal_system/ui/pages/` 配下で実装
- サイドバー選択に応じて `Home.py` が各ページレンダラーを呼び出す

**キャプチャ候補**: Home（サイドバー含む）

---

## 2. 画面・UI（各ページの目的、入力→保存の流れ、例外時の挙動）

### 2.1 案件検索（インクリメンタルサーチ＋ショートカット）
- `st_keyup` による入力と同時の検索更新
- Deep DOM Access によるショートカットキー（Alt+S）で検索欄フォーカス
- 案件選択後は `st.session_state` と `st.rerun()` で画面即時更新

**キャプチャ候補**: 案件検索（`st_keyup` の検索UIが分かる状態）

### 2.2 各種読取（登記情報/残高証明書/戸籍/法定相続情報）
- PDF/画像アップロード → AI解析 → 結果プレビュー → 編集 → DB登録
- 銀行名・支店名の表記ゆれ吸収（全銀データ参照）
- 登記情報は遺言書転記用テキスト生成も実装

**キャプチャ候補**: 各種読取（登記/残高証明/戸籍/法定相続情報）で「アップロード→結果→登録」が分かる画面

### 2.3 家系図・相続人可視化
- 戸籍読取結果を元に Mermaid で家系図を描画
- 法定相続順位を自動判定

**キャプチャ候補**: 家系図（Mermaid表示）

### 2.4 タスク管理
- 案件に紐づく標準タスクの初期化、一覧編集（完了/期限/担当等）
- 更新後は `st.session_state` のキー整理と `st.rerun()` で即時反映

**キャプチャ候補**: タスク管理（一覧編集と即時反映）

### 2.5 進捗ダッシュボード
- 全案件サマリー、SLA違反検出、ボトルネック分析、個別案件詳細の可視化

### 2.6 銀行手続き自動化UI
- 案件選択 → 口座選択 → 銀行・機能選択 → テンプレPDF選択 → PDF生成
- `st_keyup` 動的検索と Deep DOM Access ショートカットを組み込み

**キャプチャ候補**: 銀行手続き自動化（案件選択〜PDF生成の導線）

### 2.7 その他ツール類
- 預貯金口座入力ツール（銀行/支店/口座種別マスタ整備）
- 書式座標登録ツール（PDFテンプレートへの座標管理・検証）
- AI書類内容チェック（監査）
- 業務ナビ・マスタ設定（銀行ごとの注意点編集）

## 3. 自動化・外部連携（Selenium/外部APIの“できること/前提”）

### 3.1 登記情報提供サービスのブラウザ自動操作（Selenium）
- WebDriver 起動、要素待機（クリック/入力）、例外処理
- リトライ（バックオフ）による安定化
- 商業・法人モードを含む入力支援UIと連携

### 3.2 銀行手続き自動化の基盤（Selenium共通基盤）
- WebDriver 起動設定、要素待機・入力ヘルパー、リトライ
- **法人格除外ロジック**（例：株式会社等の除去）を共通部品として実装済み
- ※銀行の「解約申請（相続届/口座凍結）」は UI 上の導線は用意し、実ブラウザ操作は段階実装中

### 3.3 Gmail監視（メール連携）
- Gmail API（読み取り）により、メールを取得して案件関連ログ等に活用する基盤
- リトライ（バックオフ）や例外処理を実装

### 3.4 Kintone連携
- Kintone データ（JSON）を元にしたデータ整形・同期ロジック
- Kintone 貼付→Excel生成の UI（初回送付セット作成）を提供

### 3.5 RAG検索（ナレッジ検索）
- 遺言書等をインデックス化し、質問に対して検索＋要約回答（RAG）を行う仕組み
- 銀行規定・過去ドキュメントの検索にも対応

---

## 4. データ管理（主要テーブル概観、登録・更新の責務）

### 4.1 DB接続管理（SQLAlchemy 2.0）
- Streamlit 実行時の接続キャッシュ（`st.cache_resource`）等を用い、安定した DB アクセスを提供

### 4.2 主要テーブルと責務
- **Case**: 案件情報（依頼者、被相続人、状況等）
- **Deceased**: 被相続人情報
- **Heir**: 相続人情報
- **FinancialAsset**: 金融資産（銀行口座、証券等）
- **BankMaster / BranchMaster**: 銀行・支店マスタ
- **Task**: 案件に紐づくタスク
- **FileRegistry**: ファイル管理

### 4.3 サービス層
- **検索サービス**: 案件番号、依頼者、被相続人、連絡先（電話等）を横断検索
- **タスク管理サービス**: 標準タスク自動生成、更新、取得（例外時はロールバック）
- **進捗トラッカー**: タスク・銀行・戸籍・不動産等の状況から進捗率を算出し、ダッシュボードへ提供

### 4.4 PDF生成ユーティリティ
- テンプレートPDFに座標指定で文字を重ねる仕組み（帳票生成の基盤）
- 銀行手続き：残高証明PDF生成（テンプレPDF＋座標差し込み）
  - 対象銀行：みずほ／ゆうちょ／三菱UFJ／JA
  - 生成結果はダウンロード可能（案件・口座選択と連動）

### 4.5 Pydanticスキーマ（AI処理結果の構造化）
- 書類解析結果（照合結果、アラート等）を型付きで扱い、保存・表示に利用

## 5. 今後の予定（技術的課題と対応方針を含むが、機密は必要最小限）
1. **銀行手続き自動化（ブラウザ操作の本実装）**
   - 「解約申請（相続届/口座凍結）」の Selenium 実装を拡充（銀行ごとの画面差異に合わせて段階対応）
2. **PDF生成の拡充**
   - 銀行テンプレートの追加・差し込み項目拡張（運用テンプレの追加に追随）
3. **外部連携の運用整備**
   - Gmail/Kintone の運用手順整理、監査ログ・エラー通知の整備
4. **品質・安定性**
   - 例外時のユーザー導線（リカバリ手順）、テスト/ログの拡充

## 6. 技術スタック（現行）
- **Python**: 3.10+  
- **UI**: Streamlit  
- **DB/ORM**: SQLAlchemy 2.0  
- **データ検証/スキーマ**: Pydantic  
- **ブラウザ自動化**: Selenium（WebDriver）  
- **AI/解析**: LangChain系コンポーネント、ベクトル検索（Chroma等）  
- **PDF/画像処理**: pypdf / pdf2image / PIL / reportlab（帳票生成系）
